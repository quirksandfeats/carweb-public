Six Degrees

Pick any two — a car, a make, a designer — and trace the shortest path between them through the web.

    Request an LLM scan

    This site is a static copy — the local model runs on one machine, which is usually asleep. Pick a car and the request waits for that machine; it reads the car's Wikipedia article, looks for generations this graph is missing, and pushes what it finds back here.

    Refresh generation photos

    Re-reads each scanned article and recomputes only the picture each generation points at. The model is not involved, nothing is re-checked, and a confirmed family stays confirmed. A generation that already has a photo and finds nothing this time keeps the one it has.

    🧹 LLM Debug

    show them

      If this car is related to another, and that one is related to a third, the third is probably related to this one too. Generations are respected: a link to a whole nameplate never chains through a link to one specific generation of it.
      Suggestions are always shown for you to accept or dismiss — nothing is added on its own.

      🧪 Playground

      Build the exact prompt a real check would send, paste in a response from your own local LLM, and preview (or apply) the result -- nothing here calls llama.cpp for you unless you click "Run it here".

      🔗 Unconfirmed Relationships

      ➕ Add Car

      Type a make and model to add to the graph. It'll try to find the Wikipedia article on its own; if it can't, it'll ask you for a link.

      ✏️ Modify Existing Car

      Pick a car that's already in the graph, then fix its Wikipedia link, merge other models into it as generations, or just ask the local LLM about it.

      🗑 Delete / Restore

      Delete anything in the graph — a make, a car, a nameplate, a single generation, or a designer/engineer. Harvested (DBpedia / My Database) data can be deleted too; it's recorded separately below and can always be restored, because nothing is ever erased from the underlying data files.

      Cars and makes that weren't in the build-time snapshot — added by hand through Add Car, or created by the LLM when another car's article named one the graph didn't have yet.

      ↺ Restore puts something back. ✕ Clear removes it for good — the record disappears from this list and every trace of the car is wiped from the LLM data file, so it can never be restored or rediscovered.

      Re-harvests everything from DBpedia and Wikipedia and rebuilds data.js, so the snapshot is dated today instead of whenever it was last built. Takes a few minutes and needs an internet connection.
      Your deletions, the local LLM's findings and your My Database review decisions are all kept — they live in separate files this doesn't touch.
